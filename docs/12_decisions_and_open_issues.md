# 12. 設計判断・リスク・未決事項

## 1. 設計判断記録

### ADR-001 資金管理に機能を限定する

- 状態: 採用
- 判断: レース、馬券、血統、調教、馬体、賞金予測、推奨出資判定を実装しない。
- 理由: 中心価値を資金の記録・予定・予算へ集中し、根拠のない予測と投資助言を避ける。
- 影響: シミュレーションは支出だけを扱い、将来入金を予測しない。

### ADR-002 React SPAとAPIを単一Workerで配信する

- 状態: 採用
- 判断: Static AssetsとHono APIを1つのWorkerへ配置し、`/api/*` をWorker優先とする。
- 理由: MVPの配布単位と同一オリジンを単純化し、Cookie認証・Origin制御を扱いやすくする。
- 影響: WorkerロールバックはUIとAPIを同じ版へ戻す。大規模化時は分離を再評価する。

### ADR-003 D1を環境ごとに1データベース使う

- 状態: 採用
- 判断: local/dev/将来prodでD1を分離し、主要表は行の `user_id` でテナント分離する。
- 理由: 19表の横断集計とMVP運用を単純化する。
- 影響: 1 DBの直列書込特性を考慮し、長い更新と全件走査を避ける。

### ADR-004 金額を円単位整数で扱う

- 状態: 採用
- 判断: すべての金額を小数なしの安全な整数とする。
- 理由: JPYの表示・集計で浮動小数誤差を避ける。
- 影響: 手数料率などの率計算も最終的な円への丸め規則を明示する必要がある。

### ADR-005 予定・実績・契約を分離する

- 状態: 採用
- 判断: `scheduled_cashflows`, `cashflows`, `investments` を分ける。
- 理由: 将来見込と実際発生額を混同せず、照合と回収率を説明可能にする。
- 影響: 画面では「実績」「未払い予定」「見込」を明示し、同じ金額を重ねない。

### ADR-006 馬ステータスを自由な整理ラベルにする

- 状態: 採用
- 判断: 状態遷移を強制せず、状態変更だけで金融データを作成しない。
- 理由: クラブ・利用者ごとの運用差を許容し、暗黙の金額変更を防ぐ。
- 影響: 出資の有無は `investments`、精算の実態は `horse_settlements` で判定する。

### ADR-007 馬名変更を履歴保持する

- 状態: 採用
- 判断: 現在名を馬本体、旧名をalias表へ保存する。
- 理由: 募集名から競走馬名への変更後も、帳票と過去収支を同じ馬IDへ結び付ける。
- 影響: 同じ旧名が複数馬へ一致したときは自動選択しない。

### ADR-008 馬の削除だけ完全削除を許可する

- 状態: 採用
- 判断: 現在名の完全一致確認後、関連する出資・収支・予定・照合・精算などを物理削除する。
- 理由: 利用者が明示的に馬単位の全履歴削除を望む場合に応える。
- 影響: 復元不可。詳細監査も削除し、匿名の件数監査だけを残す。通常の業務データ削除はアーカイブを維持する。

### ADR-009 PDFはブラウザ内解析する

- 状態: 採用
- 判断: PDF.jsとWeb Cryptoを使い、PDF本体・全文をサーバーへ送らない。
- 理由: 氏名、住所、口座情報を含み得る帳票の漏えい面を最小化する。
- 影響: 画像PDF・OCR・未対応レイアウトは対象外。利用者確認を必須とする。

### ADR-010 定期予定は12か月先まで補充する

- 状態: 採用
- 判断: ルール作成・変更と日次Cronで12か月先まで生成する。
- 理由: 将来の資金見通しを提供しつつ、無期限の重複データ生成を避ける。
- 影響: 一意制約と生成済み月で冪等性を保つ。上限到達時の分割処理が将来必要。

### ADR-011 認証は交換可能なアプリ内実装から始める

- 状態: MVP採用、本番前再評価
- 判断: メール・PBKDF2・Cookieセッションを `requireAuth` 境界で提供する。
- 理由: MVP開発を進め、所有権設計を先に確立する。
- 影響: メール確認、リセット、MFA、レート制限が不足するため、一般公開前に外部IdPを含め再評価する。

### ADR-012 当面は本人限定devを安定運用する

- 状態: 採用
- 判断: 一般公開を急がず、Cloudflare Accessで本人だけを許可し、初期アカウント作成後は `ALLOW_REGISTRATION=false` とする。
- 理由: 一人利用では公開向け認証機能より、金額の重複防止、集計一致、バックアップ・復元を優先する。
- 影響: 精算は409拒否と `cashflows.idempotency_key` で冪等化し、主要APIを隔離D1で試験する。メール確認、パスワード再設定、規約、課金、prod環境は一般公開を決めるまで延期する。

## 4. 変更時の判断基準

次の変更はADRを追加または更新します。

- 実績金額の正本や回収率式を変える。
- 馬の削除範囲、復元、監査内容を変える。
- PDF本体または全文をサーバーへ送る。
- 認証方式、セッション境界、テナント分離を変える。
- D1以外の永続化、複数DB、外部サービスを導入する。
- レース・予想・推奨に関する機能を提案する。
- 課金または一般公開を開始する。
