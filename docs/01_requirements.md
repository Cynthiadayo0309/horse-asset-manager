# 01. MVP要件定義

## 1. 文書目的

本書はMVPの業務要件、機能要件、非機能要件、受入条件を定義します。要件IDは設計、実装、テスト、課題管理で共通利用します。

## 2. 前提と制約

- 対象は一口馬主活動の資金管理であり、競馬予想・投資推奨を行わない。
- Windows Web版をMVPとし、ChromeとEdgeを正式対象とする。
- PCの左サイドバー構成を基準とし、360px以上でも主要操作を可能にする。
- 金額は円単位の整数、日付は `YYYY-MM-DD`、対象年月は `YYYY-MM` とする。
- 主要データは常に認証済み利用者の `user_id` で絞り込む。
- Cloudflare Workers Paid Planの最低月額5 USDを前提とするが、従量課金を抑える。

## 3. 機能要件

### 3.1 認証・初期設定

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-AUTH-001 | 許可中だけ、利用者はメール、表示名、12文字以上のパスワードで登録できる | 重複メールは拒否し、パスワード平文を保存しない。`ALLOW_REGISTRATION=false` では登録導線を隠しAPIを403にする | 実装済み |
| FR-AUTH-002 | 利用者はログイン・ログアウトできる | 認証後はHttpOnly Cookie、ログアウト後は同じセッションを無効化する | 実装済み |
| FR-AUTH-003 | 未認証利用者を保護画面からログインへ移動する | 画面とAPIの両方で認証を要求する | 実装済み |
| FR-SETUP-001 | 初回に年間予算、月間予算、任意のクラブ名を設定できる | 保存時に初期カテゴリーとアラートルールも作成される | 実装済み |
| FR-SETUP-002 | 初期設定完了後はダッシュボードを開始点とする | 未完了利用者は `/setup` へ、完了済み利用者は `/dashboard` へ移動する | 実装済み |

### 3.2 クラブ・カテゴリー

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-MST-001 | 利用者はクラブを登録・編集・アーカイブできる | 同じ利用者内でクラブ名を重複登録できない | 実装済み |
| FR-MST-002 | 利用者は支出・入金カテゴリーを登録・編集・アーカイブできる | 種別と名称の組合せを同一利用者内で一意にする | 実装済み |
| FR-MST-003 | 初期カテゴリーをシステムコードで識別できる | 出資金、維持費などを画面ラベル変更に依存せず参照できる | 実装済み |

### 3.3 馬・出資管理

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-HORSE-001 | 候補馬と出資馬を同じ馬台帳で管理できる | 馬名、クラブ、募集情報、見込費用、締切、状態、メモを保存できる | 実装済み |
| FR-HORSE-002 | 馬一覧を状態、クラブ、検索語で絞り込める | 一覧はページングし、他利用者の馬を含めない | 実装済み |
| FR-HORSE-003 | 馬ステータスを任意に変更できる | 状態変更だけで金融データを自動作成・変更しない | 実装済み |
| FR-HORSE-004 | 馬名を編集し、以前の名前を保持できる | 変更前の名前を利用者・馬単位で重複なく保存する | 実装済み |
| FR-HORSE-005 | 馬を明示確認後に完全削除できる | 現在の馬名と完全一致しなければ409、入力不正は422、他利用者の馬は404 | 実装済み |
| FR-INV-001 | 馬に出資口数、一口価格、契約総額、出資日を登録できる | 契約総額は口数×一口価格に一致し、1馬1出資情報とする | 実装済み |
| FR-INV-002 | 出資登録時に初回支出を同時登録できる | 出資と初回支出と監査ログを同一のD1 batchで保存する | 実装済み |

### 3.4 実績収支

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-CF-001 | 支出・入金を登録・編集できる | 種別、日付、対象年月、カテゴリー、金額を必須検証する | 実装済み |
| FR-CF-002 | 収支へ任意で馬・クラブを関連付けられる | 関連先が同じ利用者に属することをAPIで検証する | 実装済み |
| FR-CF-003 | 収支一覧を期間、馬、クラブ、カテゴリー、種別で絞り込める | `pageSize` は最大100、実績集計はconfirmedだけを使う | 実装済み |
| FR-CF-004 | 収支削除は原則アーカイブとして履歴を保持する | 一覧・集計からarchivedを除外し、監査ログを残す | 実装済み |

### 3.5 定期ルール・予定・照合

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-SCH-001 | 毎月・毎年・一回の定期ルールを登録できる | 日は1〜31、開始・終了月、金額、カテゴリーを検証する | 実装済み |
| FR-SCH-002 | 定期ルールから12か月先まで予定を生成する | 月末を超える日はその月の末日とし、同じルール・期日を二重生成しない | 実装済み |
| FR-SCH-003 | 予定を手動登録・編集し、planned/paid/cancelled/overdueで管理する | 日次処理で期限超過のplannedをoverdueへ更新する | 実装済み |
| FR-REC-001 | 予定と実績を1対1で照合・解除できる | 一致・差額・実績不足・予定外実績を識別し、差額理由を保持する。解除時は実績を残し、予定を期日に応じplanned/overdueへ戻す | 実装済み |
| FR-REC-002 | 対象月の予定と実績を自動照合できる | 同一利用者内で未照合データだけを対象にする | 実装済み |

### 3.6 予算・シミュレーション

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-BUD-001 | 年間・月間予算を登録・更新できる | 利用者、種別、対象期間の組合せを一意にする | 実装済み |
| FR-BUD-002 | 年間予算に対する実績、未払い予定、見込合計、残額を表示する | 出資可能額は負数にせず0を下限とする | 実装済み |
| FR-SIM-001 | 複数候補を含むシミュレーションを保存できる | 開始月、想定月数、初回、月額、年額を検証する | 実装済み |
| FR-SIM-002 | 初回、月額、初年度、想定期間合計を計算する | 初年度は初回＋月額×12＋年額、期間は年額回数を切り上げる | 実装済み |
| FR-SIM-003 | シミュレーションと年間予算を比較する | 将来賞金を仮定せず、予算超過を表示する | 実装済み |

### 3.7 分析・台帳

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-ANA-001 | ダッシュボードに対象月の支出、入金、予定、予算、通知を表示する | 期間を限定した集計を1回の画面表示に必要な範囲で返す | 実装済み |
| FR-ANA-002 | 馬別、クラブ別、カテゴリー別、月別に分析できる | 指定期間内のconfirmed収支だけを集計する | 実装済み |
| FR-ANA-003 | 馬別台帳で出資元本、支出、入金、損益、回収率を確認できる | BR-02、BR-03の定義に一致する | 実装済み |
| FR-ANA-004 | 分析結果と収支をCSV出力できる | 期間指定を必須とし最大5年、UTF-8 BOMと数式注入対策を適用する | 実装済み |

### 3.8 引退・精算

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-SET-001 | 引退後の最終費用、売却、保険、返還、引退精算を登録できる | 予定状態で保持し、支出・入金方向を明示する | 実装済み |
| FR-SET-002 | 精算を完了して実績収支へ反映できる | 精算完了とcashflow作成を同じ更新単位で処理し、連続・同時再実行は409として二重反映しない | 実装済み |
| FR-SET-003 | 未完了精算がない馬を精算完了にできる | 未完了があれば409で拒否する | 実装済み |

### 3.9 アラート・通知

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-ALT-001 | 支払期限、募集締切、予算、実績未入力、クラブ集中の条件を設定できる | 通知方法はMVPではアプリ内だけとする | 実装済み |
| FR-ALT-002 | 日次で予定補充、期限更新、通知判定、期限切れセッション削除を行う | UTC 0:15（JST 9:15）に実行し、通知キーで重複を防ぐ | 実装済み |
| FR-ALT-003 | 通知一覧と既読操作を提供する | 他利用者の通知を取得・更新できない | 実装済み |

### 3.10 PDF帳票取込

| ID | 要件 | 受入条件 | 状態 |
|---|---|---|---|
| FR-PDF-001 | 対応するシルク・ロード帳票をブラウザ内で解析する | PDF本体、抽出全文、氏名、住所、口座情報をAPIへ送らない | 実装済み |
| FR-PDF-002 | 取込前に日付、対象月、馬、クラブ、カテゴリー、金額を確認・修正できる | 支出・入金の明細合計が帳票合計と一致するまで登録不可 | 実装済み |
| FR-PDF-003 | 予定または実績へ最大100明細を一括登録する | 取込記録と明細をD1 batchで保存する | 実装済み |
| FR-PDF-004 | 同じPDFの重複取込を防ぐ | 同一利用者・SHA-256ハッシュで409を返す | 実装済み |
| FR-PDF-005 | 現在名と旧名を馬名照合に使用する | 複数馬に一致する表記は自動選択しない | 実装済み |

## 4. 非機能要件

| ID | 分類 | 要件 | 判定基準 |
|---|---|---|---|
| NFR-SEC-001 | データ分離 | 主要な取得・更新は認証利用者の `user_id` で制限する | 2利用者E2Eで他者データが404になる |
| NFR-SEC-002 | 認証情報 | パスワードとセッショントークンを平文保存しない | PBKDF2-SHA256、セッショントークンSHA-256を確認 |
| NFR-SEC-003 | Web保護 | HTTPS、Secure/HttpOnly/SameSite Cookie、セキュリティヘッダー、同一オリジン検証を使用する | dev/prod相当設定とAPIテストで確認 |
| NFR-PRV-001 | PDFプライバシー | PDF本体・抽出全文をサーバーへ送信・保存しない | ネットワークとDB検査で確認 |
| NFR-DAT-001 | 金額整合性 | 金額は安全な非負整数とし、入力をZod・DB制約で検証する | 境界値テストで小数・負数・上限超過を拒否 |
| NFR-REL-001 | 冪等性 | 定期予定、PDF明細、通知、精算実績を重複生成しない | 同じ操作の連続・同時実行で件数が増えない |
| NFR-REL-002 | 更新整合性 | 複数テーブル更新はD1 `batch()`を用いて失敗時の中途半端な状態を避ける | 隔離D1の失敗注入統合テストで確認 |
| NFR-PERF-001 | 一覧性能 | 一覧APIはページングし、`pageSize<=100` とする | APIスキーマとテストで確認 |
| NFR-PERF-002 | 集計性能 | 分析・CSVは期間必須、CSVは最大5年とする | 期間なし・5年超を拒否する |
| NFR-USA-001 | 対応環境 | Chrome/Edgeと360px以上で主要操作を完了できる | Playwright Chromium/Chrome/Edgeで確認 |
| NFR-USA-002 | 初心者向け | ラベルは資金管理の平易な日本語とし、競馬専門用語へ依存しない | 画面レビューで確認 |
| NFR-OPS-001 | 監査 | 金額・予算・出資・削除などの変更を監査可能にする | `audit_logs` と匿名削除監査を確認 |
| NFR-OPS-002 | 観測性 | Workerのエラー、Cron、D1使用量を確認でき、機密値をログへ出さない | dev環境のWorkers Logsと運用手順で確認 |
| NFR-COST-001 | コスト | 全件取得と高頻度Cronを避け、予算通知を設定する | 設計レビューとCloudflare設定で確認 |
| NFR-MNT-001 | 保守性 | TypeScript strict、原則any禁止、共通Zodスキーマを使う | typecheck、lint、テストで確認 |

## 5. 主要受入シナリオ

### AC-01 初回利用

利用者が登録し、初期予算を保存し、候補馬を登録し、出資と初回支出を登録し、馬別台帳で金額を確認できる。

### AC-02 月次管理

利用者が定期ルールを登録すると12か月先まで予定が生成され、実績登録後に予定と照合でき、ダッシュボードの見込額が更新される。

### AC-03 PDF取込

対応PDFをブラウザで解析し、明細を確認・修正して実績へ登録できる。同じPDFの再取込は拒否され、PDF本体は送信されない。

### AC-04 利用者分離

利用者Aの馬IDを知る利用者Bが、詳細取得・更新・削除を試してもAのデータを取得・変更できない。

### AC-05 完全削除

馬名が不一致なら削除できず、完全一致後は馬関連の出資・収支・予定・照合・精算・別名が削除され、匿名件数監査だけが残る。

### AC-06 引退精算

引退馬へ精算予定を登録し、完了時に一度だけ実績収支へ反映し、未完了精算がなくなった後に馬を精算完了へ変更できる。

## 6. MVP対象外

- ネイティブアプリ、PWA配布
- 競馬予想・馬券予想・能力評価・投資推奨・賞金予測
- 画像PDF、暗号化PDF、AI OCR、汎用帳票AI解析
- 添付ファイル、R2、メール通知、ブラウザ通知
- メール確認、パスワード再設定、MFA、外部IdPは本番前の拡張候補
- 課金、一般公開、本番SLA、管理者コンソール

## 7. 要件変更ルール

- 要件を削除してもIDを再利用しない。
- 金額計算・削除範囲・プライバシー境界を変更する場合は設計判断記録と移行方針を追加する。
- 状態を変更した場合は `11_requirements_traceability.md` と関連テストを同時更新する。
